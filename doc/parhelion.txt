1. INTRODUCTION                           *parhelion* *parhelion-introduction*

Parhelion is a colorscheme that draws code in a modern take on Solarized, in
dark and in light, and gives plugin interfaces a quiet, consistent look of its
own. It follows 'background', so setting it switches modes.

Parhelion needs Neovim 0.12 or later with 'termguicolors' on, which Neovim
turns on by itself in a terminal that supports 24-bit color. Its test suite
runs on Neovim 0.12, and nothing older is tested.

==============================================================================
2. INSTALLATION                                       *parhelion-installation*

With lazy.nvim: >lua

    {
        "joaofnds/parhelion.nvim",
        lazy = false,
        priority = 1000,
        config = function()
            vim.o.background = "dark" -- or "light"
            vim.cmd.colorscheme "parhelion"
        end,
    }
<
To change an option, call |parhelion.setup()| in `config`.

Parhelion sets `g:fzf_colors` unless it is already set, so fzf-lua and fzf's
own Vim plugin draw their pickers from parhelion's groups. Turning `fzf` off
in |parhelion-plugins-option| leaves it unset, so fzf draws its own colors
inside both pickers, and a value you set yourself stays as it is.

3. OPTIONS                                                 *parhelion-options*

                                                           *parhelion.setup()*
require("parhelion").setup({opts})
    Sets the options every later load uses, and reloads parhelion when it is
    the active colorscheme so they take effect at once. Each call starts from
    the defaults, so an option left out goes back to its default. An option
    parhelion does not know, or a value of the wrong type, raises an error.
    Options hold across a 'background' toggle and a reload.

    The defaults: >lua

    require("parhelion").setup {
        transparent = false,
        dim_inactive = false,
        bold = true,
        italic = true,
        overrides = {},
        plugins = {},
    }
<
                                                       *parhelion-transparent*
transparent ~
    `true` clears the background of the page and of the gutter, so the
    terminal's background shows through. That covers every group drawn on the
    page's color, the line number, sign and fold columns, and the signs and
    line numbers drawn on the gutter's color. Floats, the cursor line, the
    selection and the other surfaces above the page keep their backgrounds.

                                                      *parhelion-dim_inactive*
dim_inactive ~
    `true` gives windows without focus a dimmer surface than the page. In
    dark mode it is a step darker than the page. In light mode it is the
    surface the cursor line and the gutter use, because no other step below
    the light page stays apart from both the page and the text, so an
    inactive window's cursor line and gutter blend into the rest of it. Code
    keeps its contrast on the dimmer surface in both modes. With
    |parhelion-transparent| on, inactive windows still take it.

                                                              *parhelion-bold*
bold ~
    `false` removes bold from every group and from the theme files in
    |parhelion-theme-files|. An override can still set it in a group.

                                                            *parhelion-italic*
italic ~
    `false` removes italic from every group. An override can still set it.

                                                         *parhelion-overrides*
overrides ~
    A table from a group name to the attributes |nvim_set_hl()| takes, or a
    function that returns one. An override merges into the group parhelion
    sets, so this keeps the keyword's color and only drops its bold: >lua

    require("parhelion").setup {
        overrides = { Keyword = { bold = false } },
    }
<
    An override that sets `link`, or one for a group parhelion links or does
    not set, replaces the group. Overrides apply after every other option.
    An override Neovim refuses, such as a color it cannot read, raises an
    error when parhelion loads, and the colors on screen stay as they were.
    When `setup` raises that error, the earlier options stay in force.

    A function is called on every load with the colors of the active mode,
    so one override works in dark and in light: >lua

    require("parhelion").setup {
        overrides = function(colors)
            return {
                CursorLineNr = { fg = colors.violet, bg = colors.raised },
            }
        end,
    }
<
    The table it gets holds:
    - `background`: `"dark"` or `"light"`.
    - The surfaces: `page`, `float`, `raised`, `selected` and `backdrop`.
    - The text steps: `hairline`, `ghost`, `quiet`, `body` and `strong`.
    - The interface's accent: `accent`.
    - The signals: `error`, `warn`, `ok` and `added`.
    - The diff fills: `added_wash`, `changed_wash`, `removed_wash`,
      `added_word_wash`, `changed_word_wash` and `removed_word_wash`.
    - The search fill: `match_wash`.
    - The staged git signs: `staged_added`, `staged_changed` and
      `staged_removed`.
    - The hues: `yellow`, `orange`, `red`, `magenta`, `violet`, `blue`, `cyan`
      and `green`.
    Reading a name not in this list raises an error.

    Parhelion's own queries mark some code in CSS, SCSS, JavaScript, TSX and
    Lua, such as the name in a Lua function call, and draw it through the
    general groups `@constant`, `@function`, `@keyword`, `@number`, `@string`,
    `@tag` and `@type`. An override of a narrower group, such as
    `@function.call` or `@function.lua`, does not reach that code, so override
    the general group to change it too.

                                                    *parhelion-plugins-option*
plugins ~
    A table from a plugin's name in |parhelion-plugins| to `false`, which
    leaves that plugin's groups to the plugin: parhelion sets none of them,
    and the plugin draws with whatever highlights it sets itself. `true`, the
    default for every plugin, keeps parhelion's groups. >lua

    require("parhelion").setup {
        plugins = { ["telescope.nvim"] = false },
    }
<
    A name not in the list raises an error. An override still sets a group of
    a plugin that is turned off.

None of them needs any setup for parhelion to color it, apart from the theme
files in |parhelion-theme-files|. Some of their own settings change how they
look with it:
- nvim-web-devicons: `color_icons = false` draws every icon in one gray, since
  a few of its own colors are dim on a dark page.
- nvim-cmp: `cmp.config.window.bordered()` draws a selected row with the
  selection's fill, and on Neovim 0.11 and later it draws no border unless
  'winborder' is set or `border = "rounded"` is passed.
- bufferline.nvim: `diagnostics` dims its counts in dark, and
  `show_buffer_icons` draws inactive icons on a shade parhelion does not
  use. Turning both off avoids this.
- alpha-nvim: the stock dashboard draws its header with `Type`, so it is
  orange. `dashboard.section.header.opts.hl` takes another group.
- neo-tree.nvim: `name = { use_git_status_colors = false }` keeps a changed
  file's name neutral, as nvim-tree's are.

5. THEME FILES                                         *parhelion-theme-files*

Some plugins load a theme of their own, and parhelion ships one for each:

lualine.nvim ~
    `theme = "parhelion"`. The stock layout puts the diff and diagnostic
    counts in section b, where they are hard to read with this theme, so
    move them to section c.

barbecue.nvim ~
    `theme = "auto"` finds it through |g:colors_name|, or
    `theme = "parhelion"`.

bufferline.nvim ~
    Nothing to set. `highlights = require("parhelion.bufferline").get_theme()`
    also works and returns no highlights, because parhelion already sets
    every `BufferLine` group the tab bar draws with.

feline.nvim ~
    `components = require("parhelion.feline").get_statusline()` in feline's
    setup. Call `require("parhelion.feline").setup {}` before it to replace
    parts of its `assets`, `settings`, `mode_colors` or `view` tables.

reactive.nvim ~
    `load = { "parhelion-cursor", "parhelion-cursorline" }`.

The barbecue, feline and reactive files read 'background' when they are
first required, so after a toggle they keep the earlier mode's colors until
Neovim restarts.

==============================================================================
6. TERMINAL THEMES                                 *parhelion-terminal-themes*

The plugin's `extras/` directory holds themes for Ghostty, kitty, WezTerm,
Alacritty and iTerm2, in dark and in light. Each gives the terminal the page,
text, cursor, selection and 16 terminal colors parhelion sets in Neovim. The
README says how to install each one.
